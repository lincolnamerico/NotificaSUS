# Handoff Session — 2026-07-30

## Resumo

Sessão focada em depurar e corrigir o fluxo de login OAuth Google e crash client-side no dashboard. Login OAuth foi confirmado funcional em múltiplos dispositivos/navegadores. Dashboard crash (t.map is not a function) corrigido com safe defaults e componentes defensivos.

## Problemas Encontrados e Correções

### 1. AccessDenied no signIn callback

- **Sintoma:** Login redirecionava para `/gestao/login` com erro AccessDenied
- **Causa:** `signIn` callback chamava `profile?.email` que vinha como `null` em alguns casos; `AUTH_URL` não configurada no Vercel
- **Correção:**
  - Adicionado `AUTH_URL=https://notificasus.vercel.app` como env var no Vercel
  - `signIn({ user, profile })` usa `user?.email` como fallback se `profile?.email` for nulo
  - Comparação com `.toLowerCase()`
  - Temporariamente bypassado com `return true` para testar o fluxo

### 2. "This page couldn't load" no dashboard

- **Sintoma:** Dashboard mostra skeleton por 1-2s, depois Next.js error boundary genérico. URL permanece `/gestao/dashboard`. Ao recarregar, header com email do usuário aparece brevemente antes do crash.
- **Causa 1:** `header.tsx` importava `signOut` de `@/lib/auth/auth` (módulo server-side com Neon/Drizzle), causando crash em "use client"
- **Causa 2:** `t.map is not a function` — um dos componentes chamava `.map()` em campo que veio como objeto em vez de array. Suspeita: `/api/usf` retornando `{ error: "..." }` em vez de array, ou campo de KPI vindo `null`
- **Correções:**
  - `header.tsx`: `signOut` importado de `next-auth/react`
  - `error.tsx` adicionado em `/gestao/(protected)/dashboard/` para capturar e exibir detalhes do erro client-side
  - `setData()` agora aplica safe defaults com `Array.isArray()` checks e fallbacks para `[]`/`{}`
  - USF fetch adicionado `res.ok` check + `.catch()` — nunca seta `usfs` como objeto não-array
  - `PorUsf`, `PorTipo`, `VolumeTemporal`, `DashboardFiltros`: defensivos contra dados não-array
